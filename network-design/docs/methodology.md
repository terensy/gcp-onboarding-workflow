# 方法論：網路拓樸怎麼選、CIDR 怎麼規劃

[README.md](../README.md) 講的是 Terraform module 怎麼運作。這份文件回答更前面的問題：**貴組織該選哪一種網路拓樸？子網路的 CIDR 範圍該怎麼切，才不會半年後因為位址不夠用又要重新規劃？**

<br>

## Step 1：先確認要不要環境互通，再選拓樸

對照最外層 [README.md 3.1 節](../../README.md#31-網路架構設計)的 4 個選項，用這幾個問題快速篩選：

1. **Dev/Staging/Prod 之間需要直接網路互通嗎？**
   - 不需要 → 選項 1（每個環境一個 Shared VPC），這是 Google 官方對多數情況的預設建議，先選這個。
   - 需要 → 進下一題。
2. **互通的流量需要 Layer-7 檢查（既有 NVA 廠商合約、法遵要求）嗎？**
   - 需要 → 選項 2（Hub-and-Spoke + 集中式 NVA）。
   - 不需要，只是要共用地端連線 → 選項 3（Hub-and-Spoke，無設備）。
3. **團隊要完全自主、服務之間只透過明確定義的端點溝通嗎？**（例如平台團隊只想暴露特定 API，不想讓消費端看到整個網路）
   - 是 → 選項 4（Private Service Connect 生產者/消費者模式），這個 repo 目前沒有對應的 module，需要另外設計。

`network-design/` 這個子專案的 `modules/shared_vpc` 對應**選項 1**。選了選項 2/3/4，這個 module 的 Host/Service Project 架構不適用，需要另外設計（選項 2/3 的 Hub-and-Spoke 連線機制，可以進一步參考最外層 README.md 3.1 節 NCC / VPC Peering / Cloud VPN 的比較表）。

> [!IMPORTANT]
> 不要因為選項 2/3/4 聽起來「更靈活、更先進」就選它們。選項 1 是 Google 官方對多數情況的預設建議，架構越簡單，日後除錯、交接、稽核都越省力。只有在真的有選項 1 解決不了的具體需求時，才往更複雜的拓樸走——複雜度是要拿來換取具體收益的，不是免費的。

<br>

## Step 2：CIDR 規劃

### 先抓總量，不要走一步算一步

子網路的 CIDR 一旦建立、開始有資源使用，要擴大範圍非常麻煩（GCP 子網路可以擴大，但前提是新範圍沒有跟別人重疊，而且很多組織的網路變更要走冗長的變更流程）。規劃前至少要想清楚：

- 每個環境（Dev/Staging/Prod）大概會有多少 Project、每個 Project 大概會有多少 VM/GKE 節點？
- GKE 的話，Pod 跟 Service 的次要範圍通常比主要範圍還大很多（一個節點預設可能佔用 /24 甚至更大的 Pod 範圍），這塊最容易低估。
- 有沒有要接地端網路？地端已經用了哪些網段？**Google Cloud 這邊的網段絕對不能跟地端重疊**，重疊了 VPN/Interconnect 接上去會直接找不到正確路由。

### 一個保守但夠用的起手式

| 用途 | 建議範圍大小 | 說明 |
|---|---|---|
| 單一環境的 VM 子網路 | 至少 `/20`（4096 個位址） | 抓大一點，比起 GCP 的免費資源，事後才發現不夠用重新規劃的人力成本高得多 |
| GKE Pod 次要範圍 | `/14` ~ `/16` | 每個節點會預留一大塊 Pod IP，不要用一般子網路的規劃邏輯去估 |
| GKE Service 次要範圍 | `/20` 左右通常夠用 | Service 用量遠比 Pod 少 |
| 跨環境／跨 Region 保留緩衝 | 每個環境之間留一段沒用到的區塊 | 之後真的要擴大某個環境的範圍時還有地方長，不用把所有位址一次分完 |

> [!TIP]
> 甲方常見的需求是「先給我們一個小小的測試網段就好，反正只是先試試看」，結果測試環境半年後變成事實上的正式環境，卻卡在當初隨便挑的 `/28`。規劃 CIDR 的時候直接照「這個環境未來會長多大」去抓，而不是照「現在測試用得到多少」去抓——多留的位址不用錢，重新規劃網段要花的人力跟停機時間才是真正的成本。

### 填進 `terraform.tfvars` 之前，先畫一張表

不需要複雜的工具，一張試算表列出「環境 / Region / 子網路名稱 / CIDR / 次要範圍」就夠，確認每一列彼此不重疊、也跟地端網段不重疊，再照 [examples/root/terraform.tfvars.example](../examples/root/terraform.tfvars.example) 的格式填進 `var.subnets`。
